How has the cost and nature of software production changed with AI-generated code?

September 25, 2026 ACQ2 by Acquired · Tobi Lütke

← See the ACQ2 by Acquired fiche

Code used to be the most expensive thing to produce, but now with AI, a lot of code that glues together infrastructure can be treated as a first draft rather than a final product. This shift allows rapid iteration and experimentation—though truly critical systems still demand the same careful engineering and oversight they always have.

The economics of software development have fundamentally shifted. Where engineers once had to write production-ready code because iteration was costly, AI-generated code now enables a different approach: ship quickly, test thoroughly, and refine. As Tobi Lütke explains in this episode, this is "extremely healthy" for how companies approach building.

Infrastructure Code and the Speed-Quality Trade-off

Not all code carries the same risk profile. Infrastructure glue—the middleware, connectors, and scaffolding that ties systems together—benefits most from this new rapid-iteration model. Generated code can serve as a credible starting point, reducing the time teams spend on boilerplate and low-risk integration work, freeing human engineers for the deeper problems.

However, this permission to iterate fast does not extend universally. Code that underpins mission-critical functions—payment systems, security boundaries, core logic that directly affects users—still requires the same level of rigor, testing, and intentionality it always did. The shift is not about lowering standards everywhere; it's about redirecting engineering effort toward the systems where human judgment and accountability matter most.

"It is a privilege of a lifetime to be part of another platform shift."

Interestingly, Lütke has built personal test harnesses to benchmark AI capabilities at Shopify, measuring where models succeed and where they fail—a concrete signal that he treats this transition as both opportunity and responsibility.

The Broader Implication: Speed Without Recklessness

The real win is not cheaper code, but faster learning. Teams can now explore more design options, prototype more aggressively, and validate ideas without weeks of engineering runway. This velocity compounds over time—companies that adapt to this new economics will ship more features, gather more user feedback, and iterate faster than those clinging to old models.

Yet the corollary is clear: organizations must develop better judgment about which code deserves scrutiny and which can be treated as provisional. This requires discipline, testing infrastructure, and a culture that respects the distinction between exploratory code and production code.
